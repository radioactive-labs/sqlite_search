# sqlite_search — Vector Search (v0.2) Design

- **Date:** 2026-07-24
- **Status:** Approved for planning
- **Builds on:** the FTS5 core (v0.1). Same interface philosophy: pg_search-style named scopes, composable relations, model-owned sync, schema.rb-safe virtual tables.
- **Next:** hybrid (v0.3) fuses this vec layer with FTS5 via RRF.

## Motivation

Add semantic (vector) search to the same gem, so a model can declare a `vec_scope` alongside its `fts5_scope` and query by meaning, not just keywords. The gem owns indexing, storage, sync, and KNN; the app supplies embeddings via a registered callback. Built on `sqlite-vec` (vec0 virtual tables) through the `neighbor` gem — the exact stack proven in `universal_chatbot`.

## Decisions log (settled in brainstorming)

| Decision | Choice |
|---|---|
| Sequencing | Vec first (this spec); hybrid is a later spec on top |
| Dependencies | `neighbor` + `sqlite-vec` are **optional** — not in the gemspec; loaded lazily with a clear error if a `vec_scope` is used without them |
| Embed sync | **Async by default** via a gem-provided ActiveJob; synchronous opt-in |
| Migration helper name | `create_vec_index` (FTS5's `create_fts5_table` is renamed to `create_fts5_index` for consistency — see Task 0) |
| Backend | `neighbor` for vec0 setup, serialization, KNN, distance |
| Embeddings | app-registered `embedder` **block**, `\|text, model:, scope:\|` → `Array<Float>`, called at index + query time (symmetric encoder) |
| Composability | `.semantic` returns a relation of the top-k ids ordered by KNN rank (filter-after-retrieve); `semantic_similarity` exposed |

## Feasibility (verified)

A local probe confirmed on SQLite 3.53.2 / sqlite-vec 0.1.9 / neighbor 1.2.0 / AR 8.1:
- `Neighbor::SQLite.initialize!` loads the extension on `:memory:` connections.
- `create_virtual_table "…", "vec0", ["id integer primary key", "embedding float[N] distance_metric=cosine"]` round-trips through `schema.rb`, and vec0 shadow tables do **not** leak into the dump.
- `has_neighbors` + `nearest_neighbors(:embedding, vec, distance: :cosine).limit(k)` produces `vec_distance_cosine(...) ORDER BY … LIMIT`, query vector bound as a blob, `neighbor_distance` exposed, correct ordering.

| | Migration | Generator | DSL | Table |
|---|---|---|---|---|
| FTS5 | `create_fts5_index :posts, :search` | `sqlite_search:fts5 … --index search` | `fts5_scope :search` | `posts_search_fts` |

## Components

### 1. Optional dependency loader — `SqliteSearch::Vec.load!`
```ruby
SqliteSearch::Vec.load!   # idempotent
```
- `require "neighbor"` and `require "sqlite_vec"`; on `LoadError`, raise `SqliteSearch::Error` with: *"Vector search needs the `neighbor` and `sqlite-vec` gems. Add them to your Gemfile."*
- Calls `Neighbor::SQLite.initialize!` (registers the extension per connection).
- Invoked when a `vec_scope` is declared, so a misconfigured app fails clearly at boot.

### 2. Embedder registration (block DSL)
```ruby
SqliteSearch.embedder do |text, model:, scope:|
  MyEmbedder.call(text, model:, scope:)   # -> Array<Float> of length `dimensions`
end
```
Stored on a `SqliteSearch.config`. A `vec_scope` may override with `embedder:` (callable or method symbol). Same callback runs at index time and query time.

### 3. Definition — `SqliteSearch::Vec::Definition`
Immutable per-scope config: `model, name, columns (against), dimensions, distance, table_name` (`"#{model.table_name}_#{name}_vec"`), plus a memoized **internal Neighbor model** (an AR class mapping to the vec table with `self.primary_key = "id"` and `has_neighbors :embedding, dimensions:`). Users never reference it.

### 4. Migration helper — `create_vec_index`
```ruby
create_vec_index :posts, :semantic, dimensions: 768, distance: :cosine, primary_key: "id"
# -> create_virtual_table "posts_semantic_vec", "vec0",
#      ["id integer primary key", "embedding float[768] distance_metric=cosine"]
```
No `backfill:` (vectors can't be copied — they must be embedded); document running `Post.reembed(:semantic)` after creating the index for existing rows. Round-trips `schema.rb`. Generator: `rails g sqlite_search:vec Post --index semantic --dimensions 768 --against title,body`.

### 5. DSL — `vec_scope`
```ruby
class Post < ApplicationRecord
  vec_scope :semantic, against: [:title, :body], dimensions: 768, distance: :cosine, sync: :async
end
```
- Ensures `Vec.load!`, registers the `Definition`.
- Defines a class scope `semantic(query = nil, k: 20, threshold: nil)` → composable relation (see §7).
- Registers `after_save_commit` (embed when an `against` column changed) and `after_destroy_commit` (delete the vec row).

### 6. Sync — `SqliteSearch::Vec::Backend` + `SqliteSearch::EmbedJob`
- `embed_and_store(record)`: build text = the `against` columns joined (blank-skipped); if blank → delete the vec row and return; else call the app `embedder(text, model:, scope:)`; validate the vector length == `dimensions` (raise `SqliteSearch::Error` on mismatch); upsert (delete + insert) into the vec table via the internal Neighbor model.
- `remove(record)`: delete the vec row (inline, cheap).
- **Async (default):** `after_save_commit` enqueues `SqliteSearch::EmbedJob.perform_later(record.to_gid.to_s, scope_name)`; the job locates the record (skips if deleted) and calls `embed_and_store`. `SqliteSearch::EmbedJob < ActiveJob::Base`, defined only when `ActiveJob` is present.
- **Sync opt-in** (`sync: :inline` on the scope, or a global config): `embed_and_store` runs directly in `after_save_commit`.
- `Post.reembed(:semantic)` (and rake `sqlite_search:reembed[Post,semantic]`): re-embed all rows in batches (enqueue jobs or inline), for bulk/backfill recovery.
- Integer-PK guard (same as FTS5 — vec0 `id` is an integer rowid).

### 7. Query — `Post.semantic(text, k:, threshold:)`
1. `nil`/blank text → `.none`.
2. Embed text via `embedder(text, model: Post, scope: :semantic)` → query vector.
3. KNN: `internal_model.nearest_neighbors(:embedding, vector, distance:).limit(k)` → ordered `[id, neighbor_distance]`; drop rows where `similarity = 1 - distance < threshold` (when given).
4. Return `Post.where(id: ids)` **ordered by KNN rank** (composable relation). Loaded records are decorated with `semantic_similarity` from the precomputed `{id => similarity}` map (via a relation-extension module, mirroring the FTS5 rank module).

**Composability (stated honestly):** KNN is top-`k`-then-filter. Chaining more conditions (`.semantic(...).where(active: true)`) narrows the retrieved k **after** retrieval, it does not constrain the ANN search itself. This is standard for vector search; documented in Limitations.

### 8. Distance metrics
`distance:` defaults to `:cosine`; `:euclidean` (L2) and `:inner_product` supported where `neighbor` + sqlite-vec provide them. Similarity is reported as `1 - distance` for cosine; for other metrics the raw `neighbor_distance` is exposed and documented.

## Error handling
- `neighbor`/`sqlite-vec` missing when a `vec_scope` is declared → actionable `SqliteSearch::Error`.
- No `embedder` registered when embedding/querying → clear `SqliteSearch::Error`.
- Embedder returns a vector whose length ≠ `dimensions` → raise.
- Un-migrated vec table → names the missing table (`posts_semantic_vec`).
- Non-integer primary key → same clear error as FTS5.

## Testing strategy
Test harness loads sqlite-vec via `Neighbor::SQLite.initialize!` and registers a **stub embedder** producing deterministic vectors (e.g. a small fixed map or a hash-seeded vector), so no real ML runs. Coverage:
- `create_vec_index` creates the vec0 table; **schema.rb round-trip** asserts `create_virtual_table "…_vec", "vec0", …` and no shadow-table leakage.
- Sync: async path enqueues `EmbedJob` with the right args (ActiveJob test adapter); sync path stores immediately; changed-column guard; destroy removes; blank `against` removes.
- Query: `.semantic` returns the correct nearest ids in rank order; `threshold` filters; `semantic_similarity` exposed; blank → `.none`; composes with `.where`.
- `reembed` recovers rows inserted via `insert_all`.
- Errors: missing embedder, dimension mismatch, missing deps (simulated).

## Packaging
- Runtime deps unchanged (`activerecord >= 8.0`). `neighbor`, `sqlite-vec`, and `activejob`/`globalid` are **development** dependencies (activejob/globalid ship with Rails at runtime; the gem only references them under `defined?` guards).
- The vec files are required, but `neighbor`/`sqlite-vec` load lazily via `Vec.load!`.

## Out of scope (v0.2)
- Hybrid fusion (v0.3).
- Embedding generation (always the app's `embedder`).
- Pre-filtered ANN (filter-before-retrieve) — vec0 doesn't support it cleanly; filter-after-retrieve only.
- Approximate index tuning / quantization.
